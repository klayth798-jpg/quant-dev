# 量化交易架构审查报告

审查日期：2026-06-16
范围：`backend/quantdev/` 全量源码 + 配置 / CI / `.env`
方法：按子系统并行审查（实盘安全链、数据持久层、研究/回测/策略、API 安全），关键结论已逐行复核。

总体判断：工程结构清晰（FastAPI + 服务分层 + 领域事件 + 实盘多层防护 + 就绪度自检），设计意图是对的。但存在**若干会直接影响真金白银的安全与正确性缺陷**，且当前 `.env` 中放着**可用的生产密钥**。下面按严重程度排列。

---

## 🔴 P0 — 立即处理

### 1. `.env` 里有可用的生产密钥（明文）
`.env` 同时包含真实的 `QUANTDEV_ADMIN_API_KEY`（授权所有写操作/急停的主密钥）和真实的 `TINYSHARE_TOKEN`，且 `QUANTDEV_ENV=production`。
- 立即**轮换这两个密钥**（它们已以明文存在于磁盘）。
- 用 `git log --all -- .env` 和 `git ls-files | grep env` 确认从未提交过历史。`.gitignore` 已忽略 `.env`（第 151 行），大概率未入库，但需亲自确认。

### 2. 实盘订单可能被重复下单（无锁 TOCTOU）
`services/live_execution.py:119-156`。幂等检查（119-127）先查 existing order，但真正写入 `live_order`（141 行 `create_live_order`）发生在 `pretrade.check` 之后。两个并发的 `submit_intent` 会**同时**通过 119-127 的“无既有订单”判断、同时下单到券商。`create_live_order` 即便命中 `UNIQUE(intent_id/client_order_id)` 也只是返回既有行，但代码**没有区分“返回的是既有订单”就跳过 `broker.submit_order`**（156 行无条件执行）。→ 一个 intent 变两笔真实委托。
修复方向：在 read-check-create-submit 全段加串行锁（或 DB 行级锁 / advisory lock），并在 `create_live_order` 返回既有行时直接短路返回，不再下单。

### 3. 非生产环境下 admin key 为空 = 全部写接口裸奔
`api.py:48-61`。当 `admin_api_key` 为空且 `environment != "production"`（默认 `development`），`require_admin` 直接放行，操作者身份取自攻击者可控的 `X-Operator` 头。任何能访问到端口的人都能触发急停、下单、改策略、注入行情。当前你的 `.env` 设了 key 所以未触发，但这是个一字之差就全开的雷。建议：无 key 一律拒绝，不分环境。

## 🟠 P1 — 高优先级

### 4. 部分写/重活接口完全无鉴权
以下 `POST` 没有 `require_admin`：`/api/backtests`（416）、`/api/factors/{id}/evaluate`（392）、`/api/risk/check`（456）、`/api/agent/research`（598）。可被匿名调用，无限堆积昂贵的回测/因子任务、驱动研究 Agent（成本/DoS）。此外**所有 GET 接口零鉴权**，包括 `/api/live/broker`、`/api/paper/account`、持仓、委托、对账——账户与盈亏状态对外裸露。

### 5. 单日亏损熔断可被“开盘跳空 / 首单延迟”绕过
`store.py:1104-1111` + `pretrade.py:133-141`。`start_equity` 在当天第一次写快照时才惰性确定；若当天首单发生在权益已经下跌之后，`start_equity` 锚定到已经缩水的权益，`daily_pnl` 从接近 0 起算，真实日内亏损量不到。→ 日亏损限额形同虚设。应在**每个交易日开盘前**用昨收权益固化 `start_equity`。

### 6. 实盘“纵深防御”对真实券商不成立
`integrations/broker.py`。Mock 券商的 `submit_order` 里重跑了 `live_guard.check_live_order` 作为最后一道防线，但**真实券商适配器路径没有这一层**。一旦 `submit_intent` 的前置检查被绕过或读到陈旧状态（见 #2/#5），真实下单没有独立守门。`live_guard.py` 注释里宣称的三层防御对真金白银是假的。

### 7. 回测/因子存在前视偏差（look-ahead），上真实数据后必然虚高
- **复权因子前视**：`factors.py:74-76` 用**最新快照的 `adj_factor`** 去复权历史价计算因子，把未来除权除息信息泄露进历史截面。Demo 里 `adj_factor=1.0` 掩盖了这点，换真实数据即暴露。
- **前向收益按“行偏移”而非“交易日偏移”**：`factors.py:326-333` 用 `rows[index+forward_days]`，遇停牌则不同标的的前向窗口实际跨越不同日历长度，IC 不可比。
- **停牌票按陈旧价标记**：`backtest.py` 对 T+1 不在 `close_map` 的停牌票静默跳过，权益用上一已知价，复牌后又当作可连续交易。
- **ST/幸存者偏差**：`backtest.py:60-67` 用**当前**ST 标记套用整段历史；价格面板只含当前在册标的，退市票缺失。
- **重叠窗口年化**：`factors.py:349-363` 把按日采样的重叠前向收益当独立非重叠区间年化，IC-IR 约虚高 `sqrt(forward_days)` 倍、多空收益虚高约 `forward_days` 倍。

### 8. 金额全程用 float / SQLite REAL
所有价格、现金、成交价、费用、权益、PnL 都是 IEEE-754 浮点（`db.py` 各 REAL 列；`tushare_sync.py:411-412,458-462` 用浮点乘子做单位换算）。对账时（`reconciliation.py`）浮点漂移会产生虚假 break、PnL 不精确。建议改为整数分或 `Decimal/NUMERIC`。

## 🟡 P2 — 中等

- **回测与纸面引擎成交模型不一致**：回测用 close±bps（`backtest.py:14-17`），纸面引擎用 bid/ask±bps（`execution.py:57-81`）；回测无 T+1 锁定可当日卖出买入票（`backtest.py:232-279`）。两者无法对账，回测比实际更乐观。
- **对账精度问题**：`reconciliation.py:27` 现金容差 `0.01` 用 `>` 比较，恰好 1 分的真实漂移落在边界被当作平衡；只比总持仓不比 `sellable_quantity`（A 股 T+1 核心）。
- **sync_broker 静默丢成交**：`live_execution.py:231-258` 对每笔券商成交线性扫描本地订单，找不到匹配就 `continue` 丢弃 → 真实成交可能凭空消失。
- **Postgres 全局单锁**：`db.py:905` 所有 `immediate` 事务抢同一把 `pg_advisory_xact_lock(817412)`，吞吐瓶颈；`domain_events.seq` 无 UNIQUE，并发下可能重复。
- **热路径全表扫描**：`tradability.py` / `quotes.py` 每次行情写入/涨跌停校验都 `list_instruments()` 全表 Python 端线性查找，应改索引 `WHERE symbol=?`。
- **审计写在事务外**：`store.py:838-845` 状态 UPDATE 提交后才写 audit，二者非原子，崩溃会丢审计。
- **模型校验缺口**：`models.py` 未拒绝 NaN/Inf（pydantic v2 默认接受 `inf`），无 A 股 100 股整手/最小变动价校验，`bid<=price<=ask` 仅在 service 层校验。
- **纸面账户现金可为负**：`execution.py:689` 不利行情下市价单成交 `new_cash = cash - gross - fees` 无下限保护。
- **撤单失败留模糊态**：`live_execution.py:201-217` `CANCEL_FAILED` 既非活动也非终态，无强制重查。

## 🟢 P3 — 低 / 工程卫生

- CI（`.github/workflows/ci.yml`）跑了 ruff + pytest（好），但无 `pip-audit` 依赖扫描、无覆盖率门槛；CI 用 Python 3.11 而 `pyproject.toml` 声明 `>=3.9` 且本地 venv 是 3.9 —— 最低支持版本从未在 CI 跑过。
- 前端兜底路由 `api.py:654-659` 路径穿越防护方向正确，但会 serve `frontend/` 下任意文件（含误放的密钥/源码），建议加扩展名白名单。
- 任务重投非幂等：`factor_evaluate` 重投会重复写 `save_factor_run`（`tasks.py` / `backtest.py:143-145` 仅 backtest 靠 `run_id` 幂等）。
- 依赖精确 pin（好）但无 hash 锁文件。
- `daily_indicators` 主键缺 `snapshot_id`，多 provider/快照下会跨快照覆盖。

---

## 建议处理顺序
1. 轮换 `.env` 两个密钥并确认未入库（#1）。
2. 堵 `require_admin` 无 key 放行 + 给 4 个裸奔 POST 加鉴权，决定 GET 的授权策略（#3、#4）。
3. 实盘下单加串行锁修双重下单，修日亏损 `start_equity` 锚点，给真实券商适配器补 `live_guard` 兜底（#2、#5、#6）。
4. 接真实数据前，先修前视/幸存者偏差与重叠窗口年化，否则回测结论不可信（#7）。
5. 金额改定点数（#8），统一回测与纸面引擎成交模型。
